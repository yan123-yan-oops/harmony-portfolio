# 面试通 —— AI 面试题库（项目复盘）

> 个人项目 · 2025.09–2025.10 · HarmonyOS NEXT / ArkTS
> 源码仓库：https://github.com/yan123-yan-oops/QuestionBank （master 分支）
> 本页是项目复盘，重点记录设计取舍与踩过的坑。

## 项目定位

面向求职者的面试题库 App：按岗位分类浏览题目、搜索、收藏，内置 AI 答题助手与录音练习。
目标不是"又一个题库"，而是把**刷题 → 问 AI → 开口练**这条路径串起来。

## 我的角色

独立完成：需求拆解、页面与组件、网络层、AI 接入、录音模块、联调与自测。

## 架构

```
pages/          页面（题库、搜索、收藏、AI 问答、录音练习）
viewmodel/      页面状态与业务编排
services/       网络层、AI 客户端、录音封装
model/          接口契约与领域模型（含 snake_case ↔ camelCase 映射）
utils/          登录态、格式化
```

**分层原则**：页面不拼请求体、不写存储细节；服务层不碰 UI 状态；接口字段转换只有一个入口。

## 四个关键设计

### 1. 网络层四层封装

**问题**：每个页面各写一遍请求，Token 注入、错误提示、401 跳转重复且容易漏。

**做法**：

| 层 | 职责 |
| --- | --- |
| 请求层 | axios 实例、baseURL、超时 |
| 拦截层 | 请求拦截注入 Token；响应拦截统一剥壳、错误归一、401 跳登录 |
| 业务层 | 每个接口一个函数，只关心参数与返回类型 |
| 模型层 | 接口类型定义与字段映射 |

**收益**：新增接口只写业务层一个函数；鉴权与错误处理只改一处。

### 2. AI 请求与业务请求隔离

**问题**：AI 问答的超时是 60 秒，与业务接口共用拦截器会互相干扰（业务 401 逻辑会误伤 AI 请求）。

**做法**：给 AI 单独建 axios 实例，不挂业务拦截器；用 OpenAI 兼容格式拼多轮上下文。

**收益**：两条链路互不影响，AI 超时不影响业务请求。

### 3. 登录态持久化

**问题**：App 重启后登录态丢失，各页面各自判断，体验割裂。

**做法**：Token 存 `AppStorage`，封装统一的登录状态工具类（读/写/清除），启动时恢复。

**收益**：重启自动恢复登录；页面不需要知道 Token 存在哪。

### 4. 录音生命周期封装

**问题**：`AVRecorder` 的启动、录制、保存、回放散落在页面里，容易漏释放。

**做法**：封装 `AVRecord` 工具类，统一管理"启动 → 录制 → 保存 → 回放"，用回调驱动 UI 状态。

**收益**：录制与回放无缝切换；页面退出自动释放资源。

## 数据流

```
用户输入 → ViewModel 组装参数 → Service 调 API → 模型映射 → 列表状态更新
                                            ↘ 失败：拦截层归一错误 → 页面提示
```

## 复盘

**做对了**：先把网络层和登录态抽出来，后面加页面几乎不用改基础设施。

**没做好**：
- 列表分页只做了基础版，没有预取下一页，快速滑动会短暂空白；
- AI 上下文没有做截断策略，长对话会超出 token 上限；
- 录音没有做波形可视化，用户不知道有没有录进去。

**如果重做**：先定义错误码契约，再写页面；AI 对话加滑动窗口截断。
